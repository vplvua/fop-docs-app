## Why

Сьогодні, щоб поставити власний (ФОПівський) підпис на акт, користувач має натиснути «Перейти в Дубідок» і покинути додаток — підписати на `my.dubidoc.com.ua`, повернутись і вручну оновити статус. Це зайвий контекст-світч у найчастішій дії. Дубідок надає публічне sign-посилання (`POST /documents/{id}/links`), яке можна вбудувати в `<iframe>` — той самий підхід уже працює в проді в нашому застосунку zbory. Це дозволяє підписувати акт, не покидаючи сторінку деталей.

## What Changes

- На сторінці деталей акта зʼявляється кнопка **«Підписати тут»**, доступна коли акт у статусі `sent_to_edo` (відправлено, чекає підпису ФОПа) і `edo_provider = dubidoc`. Кнопка стоїть поряд із наявною «Перейти в Дубідок» (її лишаємо як fallback).
- Кнопка відкриває **модалку з `<iframe>`**, у який завантажено публічне sign-посилання Дубідок. Уся криптографія підпису (ІІТ/Дія/Mono/SmartID) лишається в UI Дубідок усередині iframe — власної крипто-логіки НЕ додаємо.
- Sign-посилання отримується через новий виклик `POST /api/v1/documents/{id}/links { action: "sign" }`.
- Після успішного підпису ФОПа додаток **відкликає публічне посилання** через `DELETE /api/v1/documents/{id}/links` і оновлює статус акта наявним `refreshDubidocStatusAction` (`new → waiting_for_client_sign`).
- Скоуп — **тільки перший підпис (ФОП, власник документа)**. Підпис клієнта (`participant`) лишається віддаленим за листом-посиланням від Дубідок — його НЕ чіпаємо.
- Логіку завантаження акта в Дубідок (`send-to-dubidoc.ts`) **не змінюємо**: лишаються обидва сценарії — (а) просто завантажити, (б) завантажити і одразу підписати в додатку.
- Додаємо `frame-src` для домену Дубідок у Content-Security-Policy застосунку (передумова для роботи iframe).

### Modified Capabilities

## Impact

- **API-клієнт** `lib/external-apis/dubidoc/`: новий `generateSigningLink(docId)` (POST `/documents/{id}/links`), новий `deleteSigningLinks(docId)` (DELETE `/documents/{id}/links`), тип `GenerateLinkResponse`, реекспорт в `index.ts`.
- **Server actions** `app/(dashboard)/acts/[id]/act-actions.ts`: `getSigningLinkAction(actId)` → `{ url }`, `revokeSigningLinkAction(actId)`.
- **UI** `app/(dashboard)/acts/[id]/`: новий компонент модалки `dubidoc-signing-widget.tsx` (iframe), кнопка-тригер у `edo-controls.tsx`, підключення в `act-detail-panel.tsx`.
- **CSP**: додати `frame-src` домену Дубідок (наразі CSP явно не налаштований).
- **Зовнішня залежність / ризик**: чи дозволяє Дубідок вбудовування свого sign-URL в iframe (`X-Frame-Options` / `frame-ancestors` на їхньому боці). Потрібен spike-перевірка перед фіналізацією UI (zbory робить це в проді, але на публічній сторінці).
- **Auth/безпека**: публічне sign-посилання дає доступ будь-кому з URL — мінімізуємо вікно, відкликаючи його одразу після підпису.
- Без змін у схемі БД, без міграцій.
